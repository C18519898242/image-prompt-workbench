# Grok 图片生成支持设计

## 1. 背景

当前生成工作台只提供“Nano Banana 2”模型选项，后端固定通过 Gemini 原生接口生成图片。项目需要新增 Grok 图片生成能力，并继续复用现有工作台、批次调度、生成历史和图片存储流程。

已验证目标 Grok 网关不通过 `/v1/images/generations` 提供 Build 账号图片生成。可用链路是调用 `/v1/responses`，由 `grok-4.5` 使用服务端 `image_generation` 工具返回 Base64 编码图片。因此 Grok 必须作为独立生成器接入，不能复用 Gemini 请求协议。

## 2. 目标

- 在生成工作台的模型下拉框中新增“Grok Imagine”。
- 保持现有 `POST /api/generations` 前端接口不变，由后端按模型显示名选择 Gemini 或 Grok 生成器。
- 支持 Grok 文生图和最多 8 张参考图输入。
- 将用户选择的图片比例明确写入 Grok 提示词。
- 继续复用现有图片落盘、生成历史、批次串行调度和失败展示流程。
- 通过环境变量配置 Grok 网关、密钥和实际模型，不把密钥写入代码或日志。

## 3. 非目标

- 不增加 Grok 视频生成。
- 不增加账号或密钥管理后台。
- 不动态读取 Grok 上游模型列表。
- 不把整个图片生成模块重构为通用插件框架。
- 不承诺 Grok 图片工具支持显式分辨率或思考级别控制。
- 不改变数据库结构和已有历史数据。

## 4. 方案选择

采用“后端生成器路由”方案：保留统一业务接口和生成历史，根据前端提交的模型显示名选择对应生成器。

未采用独立 Grok API 路由，因为它会复制前端批次调度、错误处理和历史写入逻辑。未采用完整 Provider 插件系统，因为当前只有两个生成后端，通用插件框架超出本次范围。

## 5. 配置设计

`Settings` 新增以下配置：

- `GROK_API_KEY`：Grok 网关密钥，默认空字符串。
- `GROK_BASE_URL`：Grok OpenAI 兼容接口基址，默认 `https://grok-api.xyz365.tech/v1`。
- `GROK_MODEL`：Responses API 使用的实际模型，默认 `grok-4.5`。

根目录 `.env` 已被 `.gitignore` 排除，并由 `docker-compose.yml` 的 `env_file: .env` 传入后端容器。密钥写入根目录 `.env`，不得写入源码、测试夹具的真实值、日志或错误响应。

模型显示名与后端配置的映射固定为：

| 界面显示名 | 生成器 | 实际模型来源 |
| --- | --- | --- |
| Nano Banana 2 | Gemini | `GEMINI_MODEL` |
| Grok Imagine | Grok Responses API | `GROK_MODEL` |

提交未知模型显示名时返回 422，避免把任意前端字符串仅作为历史标签接受。

## 6. 后端组件设计

### 6.1 共享图片类型

现有 `ReferenceImage` 和 `GeneratedImage` 不再由 Gemini 专属模块拥有。把它们移动到独立的共享图片类型模块，供 Gemini 生成器、Grok 生成器和生成路由共同引用。类型仍只包含 MIME 类型和二进制数据，不包含密钥或传输细节。

### 6.2 Grok 生成器

新增 `backend/app/grok_image_generator.py`，职责如下：

1. 构造 `/responses` 请求 URL。
2. 构造文字输入或文字加参考图的多模态输入。
3. 调用 `image_generation` 服务端工具。
4. 提取第一个 `image_generation_call.result`。
5. 校验 Base64、图片格式和图片内容。
6. 将网络错误和上游错误转换为不泄露敏感信息的领域异常。
7. 对可恢复失败执行有限重试。

无参考图时，请求中的 `input` 使用字符串。存在参考图时，`input` 使用一条用户消息，其 `content` 先包含 `input_text`，再按上传顺序追加 `input_image`。每张参考图转换为 `data:<mime-type>;base64,<data>` Data URL。

工具配置使用：

```json
{
  "type": "image_generation",
  "action": "auto"
}
```

`action: auto` 允许无参考图时生成新图，也允许存在参考图时由 Grok 执行参考生成或编辑。`tool_choice` 明确选择 `image_generation`，避免只返回文本而不生成图片。

### 6.3 比例提示

Grok 图片工具不接收独立比例参数。生成器在用户提示词前增加一条简短约束：

- 选择 `Auto`：不添加比例约束。
- 选择具体比例：增加“最终图片必须为 `<比例>` 画幅。”。

用户原始提示词保持不变并紧随比例约束。比例只注入一次，避免为规避网关超时而无意义扩写提示词。

### 6.4 分辨率与思考级别

Grok 路径不向上游发送 `resolution` 和 `thinking_level`。这两个字段仍保留在现有表单和后端接口中，以维持统一接口以及生成历史字段兼容；后端只对它们执行现有枚举校验。

Gemini 路径继续完整使用比例、分辨率和思考级别。Grok 历史记录保存用户提交的分辨率字段；由于前端在 Grok 模式下固定为 `1K`，该值只作为现有历史结构的兼容占位，不表示上游尺寸控制结果。

### 6.5 路由分派

`POST /api/generations` 在完成认证、提示词、比例、分辨率、思考级别、参考图和提示词卡片校验后，根据 `model` 分派：

- `Nano Banana 2`：要求 `GEMINI_API_KEY`，调用现有 Gemini 生成器。
- `Grok Imagine`：要求 `GROK_API_KEY`，调用新增 Grok 生成器。
- 其他值：返回 422“暂不支持该模型”。

两条路径返回相同的共享 `GeneratedImage`。后续原子写图、历史创建、失败时清理文件的流程保持一致。

应用状态分别保存 Gemini 和 Grok 生成器函数，测试可以独立替换任一生成器，不发真实网络请求。

## 7. 前端设计

### 7.1 模型选项

模型下拉框包含：

- `Nano Banana 2`
- `Grok Imagine`

默认值继续为 `Nano Banana 2`，不改变现有用户行为。提交 Grok 时，历史和临时卡片中的模型名统一记录为 `Grok Imagine`。

### 7.2 参数状态

选择 `Grok Imagine` 时：

- 比例可选，并由后端注入提示词。
- 生成数量可选，继续由现有前端批次逻辑串行调度。
- 分辨率固定为 `1K` 并禁用，旁边显示“由 Grok 自动决定”。
- 思考级别固定为 `minimal` 并禁用，旁边显示“由 Grok 自动决定”。
- 参考图上传保持可用。

从 Grok 切回 `Nano Banana 2` 时，分辨率和思考级别恢复可用。为避免不可见的旧参数造成困惑，切换到 Grok 时立即归一化为上述固定兼容值。

### 7.3 参考图

沿用现有最多 8 张、PNG/JPEG/WebP 的上传和预览交互。前端不区分“参考生成”和“编辑”，只把文件传给统一 `/api/generations`；语义由提示词和 Grok `action: auto` 决定。

## 8. 数据流

1. 用户在工作台选择 `Grok Imagine`、比例、数量，并可添加参考图。
2. 前端归一化不适用参数，向现有 `/api/generations` 提交一张生成请求。
3. 后端校验请求并选择 Grok 生成器。
4. Grok 生成器将比例约束、提示词和参考图编码为 Responses API 请求。
5. 网关返回 `image_generation_call`，生成器解码并验证图片。
6. 路由原子写入 `data/generated-images/`，创建生成历史并返回 201。
7. 前端把加载卡片替换为完成卡片，并按现有批次规则处理下一张。

## 9. 超时、重试与错误处理

Grok 客户端请求超时默认 120 秒，使本项目不会先于目标网关中断。目标网关自身可能存在约 30 秒的上游响应头超时，本项目无法绕过该限制。

重试规则与 Gemini 保持一致的边界：

- HTTP 429 和 5xx 最多尝试 3 次。
- 网络错误、无效 JSON、缺少图片、无效 Base64 或无效图片最多尝试 3 次。
- 401、403 和其他明确 4xx 不重试。
- 重试采用简单递增等待，不引入队列或后台任务。

日志记录生成器名称、提示词卡片 ID、实际模型、比例、当前尝试次数和安全错误摘要。日志禁止记录 Authorization、API Key、完整请求体、参考图 Data URL 和返回图片 Base64。

路由对前端继续返回简短错误：配置缺失返回 503；请求参数错误返回 422；上游或写入失败返回 502。

## 10. 文档与密钥落地

README 增加 Grok 环境变量、支持能力和参数限制说明。根目录 `.env` 写入当前 Grok 网关配置，但 `.env` 不加入 Git。提交中只包含不含真实密钥的文档和源码；如需示例，使用占位值。

## 11. 测试设计

### 11.1 Grok 生成器单元测试

- 无参考图时构造字符串 `input`。
- 有参考图时构造 `input_text` 和按顺序排列的 Data URL `input_image`。
- 具体比例被注入一次，`Auto` 不注入。
- 请求 URL、Bearer 头、模型、工具和工具选择正确。
- 从 `image_generation_call` 提取并验证 JPEG/PNG。
- 拒绝缺少图片、非法 Base64、空图片和不可识别图片。
- 429、5xx、网络错误和无效响应会重试，不可恢复 4xx 不重试。
- 错误信息不包含密钥或图片数据。

### 11.2 路由测试

- `Nano Banana 2` 只调用 Gemini 生成器。
- `Grok Imagine` 只调用 Grok 生成器，并传入提示词、参考图和比例。
- 缺少对应 API Key 时返回 503。
- 未知模型返回 422。
- Grok 成功后写图片和历史，失败时不写历史。

### 11.3 前端测试

- 模型下拉框同时显示 `Nano Banana 2` 和 `Grok Imagine`。
- 选择 Grok 后分辨率和思考级别被禁用并显示说明。
- 切换到 Grok 时不适用参数被归一化。
- 切回 Gemini 后参数恢复可用。
- Grok 提交仍包含统一接口要求的字段、比例和参考图。
- 批次串行、加载状态、失败状态和历史去重行为保持不变。

### 11.4 完整验证

- 运行后端完整测试。
- 运行前端完整测试。
- 运行前端生产构建。
- 使用测试替身验证自动化流程，不在测试套件中调用真实 Grok。
- 可选人工冒烟测试通过 `.env` 中的真实配置生成一张图片。

## 12. 验收标准

- 工作台可选择 `Grok Imagine` 并生成图片。
- Grok 文生图和带参考图生成均能进入现有历史流程。
- 具体比例明确传递给 Grok；`Auto` 不强制比例。
- Grok 模式不会误导用户认为分辨率和思考级别可控。
- Gemini 现有行为和默认选项不变。
- 未配置、未知模型和上游错误得到明确且安全的响应。
- 源码、提交、日志和测试输出中不存在真实 Grok 密钥或图片 Base64。
- 前后端测试与生产构建全部通过。
